# REST API contract

Each line restates a decision and names it. If a line disagrees with its source, the source wins and you raise it (rule D2). A rule with no source is not written here (rule D1). The route-level mechanics (providers, commits, guard order) are in `routes-convention.md`; layer rules in `project-structure.md`.

## Shape
1. Routes live under `/api/v1`, one `APIRouter` per module with its own tag (ADR-0003, ADR-0011). Bodies are JSON, except file upload, which is `multipart/form-data` (ADR-0009). Field names are camelCase, as in the Node base (`docs/api/ENDPOINTS.md`).
2. Request and response bodies are Pydantic models. A response model is never an ORM object, and every route declares one, except a 204 and the content route of task 8.3, which is named in `BYTE_ROUTES` of `tests/unit/test_response_models.py`; that test fails for any other route (ADR-0003, task 4.1).
3. Request models extend `StrictModel` (`extra="forbid"`) and use the field types of `app/core/validation.py` (email, a new password of 8 to 72 bytes, a current password of 1 to 72, phone, UUID, no control characters); a field not in the model is a 422, not ignored (task 4.3).
4. Response shapes are fixed; there is no field selection (ADR-0003).
5. A response never carries a stored hash or salt, an `AccountIdentity`, a password-reset token, or the one-time sign-in code outside `local`, `development` and `test` (ENDPOINTS.md `signInOtp` and `restorePassword`, ADR-0028). It does carry what the contract lists: the access and refresh tokens of a sign-in, and the profile's phone number and date of birth. Logs are the place the no-secrets rule applies (rules D8, P4).

## Errors
6. Every error uses one body, `{"error": {"code", "message", "details"}}`, built in `app/core/errors.py`; FastAPI's `{"detail": ...}` never appears. The codes and their statuses are the table in `docs/api/ERRORS.md` (ADR-0003). Clients key on `code`, never on `message`.
7. `UNAUTHORIZED` (401) is the only code that tells a client to refresh a token. A wrong email, password or code is `INVALID_CREDENTIALS` and never triggers a refresh. A route that must not reveal whether an account exists answers the same for every case (the sign-in, OTP verify and restore routes: ENDPOINTS.md).
8. A new error code changes the contract: a superseding ADR for ADR-0003, a row in `ERRORS.md`, a regenerated `openapi.json` and a test in `tests/integration/http/test_http_errors.py` (ERRORS.md "Adding an error").
9. A 500 has no stack outside `APP_ENV=local`. A body over `MAX_REQUEST_BODY_BYTES`, or an upload over `FILE_MAX_SIZE`, is 413 (tasks 1.6 and 8.1).

## Who may call
10. Guard order on a protected route is authenticate (401), then role (403), then per-record ownership inside the service, rule P7. A route whose record comes from the token (`GET /account`, sign-out, change-password) needs authentication only; a route that takes another record's id keeps all three layers (ADR-0022). What an unowned id answers is per route: for a file, an unknown id and another account's file are the same 403 (ENDPOINTS.md mapping decision 3); `PATCH` of a missing profile is 404 (decision 2). The file routes (task 8.2) take `ADMIN` or `CUSTOMER` and check ownership in the service (ENDPOINTS.md "Built in task 8.2").
11. On `GET /account`, a valid token whose account is missing or soft-deleted is 401 `UNAUTHORIZED` with the Bearer challenge (ADR-0022, which adds that only this route rejects a deleted account today). Other routes differ and ENDPOINTS.md is the reference: sign-out answers 204 for a deleted account, change-password 401 `INVALID_CREDENTIALS`, and the refresh 401 carries no challenge. The refresh token travels in the `x-refresh-token` header on `POST /auth/refresh` and is stored as a sha256 hash (ADR-0008, rule P5).

## Files
12. Upload is `POST /api/v1/files` (multipart: `file`, optional `name`); size comes from the bytes and the mime type from the upload, both validated; download is an authenticated owner-only `GET /api/v1/files/{id}/content` with `Content-Type` and `Content-Length`; bytes stay in Postgres (ADR-0009). Nothing returns a base64 or `data:` body.

## The generated contract
13. `openapi.json` at the repo root is generated by `uv run python -m app.cli --export-openapi` and never edited by hand; a route change regenerates it in the same PR. `tests/unit/test_openapi_stale.py` and the CI step `python -m app.cli --export-openapi --check` fail when it is stale (ADR-0003, ADR-0020, ADR-0032, `protected-paths.md`).
14. A route added or changed updates `docs/api/ENDPOINTS.md` in the same PR (rule E1).
15. Every response carries `X-Request-ID`, and every response the app sends carries the four security headers of `app/core/security_headers.py` unless a route sets one itself; an unhandled 500 has the id but not the headers. `/docs`, `/redoc` and `/openapi.json` exist only for `APP_ENV` `local` and `development` (ADR-0033, ENDPOINTS.md).

# POC-1.4 — Quality tooling, settings and the app factory (includes POC-1.5)

Scope-doc rows 1.4 and 1.5 (rev 117) done as one task and one PR, as volodymyr asked. Ticket ID for branch and commits: `POC-1.4`;
every commit that belongs to row 1.5 also names `POC-1.5`.

## Problem
The repo has no lint, format, type-check or test command (every row of the command map is `none`) and no runnable service, so
rule B1 has nothing to gate on and no later task (2.1 database, 3.2 HTTP test client, 4.x contract) has an app to attach to.

## Goal / business value
Goal 1 (scaffolding): a fork gets one `uv run` command per check and a server that answers on a known port.
Goal 3 (test base): pytest runs from the first commit and the first tests are the ported CORS ones.

## Scope
- in (1.4): ruff (lint and format check; rules `B`, `S`, `ASYNC`, `T20` on top of the defaults), mypy strict, pytest, pytest-asyncio,
  pytest-cov, httpx (test client); config in `pyproject.toml`; the command map in `CLAUDE.md` (new `typecheck` and `format` rows);
  the `allow` list in `.claude/settings.json` for the new commands (ADR-0007 follow-up).
- in (1.5): `app/config.py` (pydantic-settings, validated once), `create_app()` with lifespan in `app/main.py`,
  `CORSMiddleware` from `CORS_ORIGINS`, `GET /api/v1/health`, uvicorn on `PORT` (default 3001), env templates, the ported
  `cors-origins.spec.ts` (4 cases), I.7 (template says 15 min).
- **out (explicit):** database, Redis, JWT and `FILE_*` settings (they enter `Settings` with the tasks that read them: 2.1, 4.x, 6.1,
  7.x, 8.x); logging, Sentry, body limit (1.6); error body and handlers (4.2); `openapi.json` export (4.1); Docker and compose
  (11.1, 11.2); CI (11.4, rule T4); the test layout rule rewrite (3.3); HTTP test client helpers and the DB fixture (3.1, 3.2);
  `--reload` and process managers.

## Acceptance criteria
- [x] AC1 Given a fresh clone, `uv sync` installs runtime and dev dependencies; `uv.lock` is regenerated by `uv`, not by hand.
- [x] AC2 Every row of the new command map runs green on the repo: lint, format check, typecheck, tests, e2e, build.
- [x] AC3 mypy runs in strict mode over `app` and `tests` with no `type: ignore`; ruff has no `# noqa`.
- [x] AC4 `Settings` is built once; a missing or invalid value stops boot with a readable error; `CORS_ORIGINS` accepts a comma list,
  falls back to `http://localhost:5173,http://localhost:5174` when unset, empty or blank, and replaces rather than extends the defaults.
- [x] AC5 Given the server runs, `GET /api/v1/health` answers 200 `{"status": "ok"}` on port 3001 (or `PORT`).
- [x] AC6 A CORS preflight (`OPTIONS /api/v1/health`) from `http://localhost:5173` is allowed; from an unknown origin it gets no allow-origin header.
- [ ] AC7 `.env.example` and `.env.development.example` exist, list every variable of ADR-0010, and set `JWT_ACCESS_TOKEN_EXPIRES_IN=15m`; no real `.env` is committed.
- [x] AC8 `RUNBOOK.md`, `ARCHITECTURE.md` and `docs/api/ENDPOINTS.md` match what now exists.

## Edge cases
| Case | Expected behaviour | Decided by |
|------|--------------------|-----------|
| `PORT` not a number | boot fails with the field name in the message | pydantic validation |
| `APP_ENV` outside `local`, `development`, `test`, `production` | boot fails | this plan |
| `CORS_ORIGINS=" , "` | defaults apply | Node `cors-origins.spec.ts` |
| Unknown origin on a simple GET | request answered, no `access-control-allow-origin` header | Starlette default |
| `pytest` collects zero tests | exit code 5 would break "green on the empty project", so R1 ships one smoke test | this plan |
| A `.env` exists in the working directory during tests | tests set variables with `monkeypatch` and build `Settings(_env_file=None)` | testing-python rule 7 |

# POC-4.3 — Validation

## Problem
Task 4.2 gave every error one body, but no request model exists yet: `app/schemas/*.py` are docstring-only, so nothing enforces the input rules the Node DTOs had (`docs/api/ENDPOINTS.md`, "Shared validation rules"). Tasks 5.4, 7.x and 8.x each need the same email, password, phone and UUID checks; written per route they drift.

## Goal / business value
Goal 2 (authentication): one place defines what a valid email, password or phone is, so the auth routes cannot disagree. Goal 1 (scaffolding): a fork adds a request model by inheriting one base class and reusing the field types.

## Scope
- in: `app/core/validation.py` (strict base model and reusable field types), the request models of the REST map in `app/schemas/auth.py` and `app/schemas/account_profile.py`, tests, docs. Runtime dependencies `email-validator` and `phonenumbers` (approved by the owner on 2026-11-03, rule C2).
- **out (explicit):** routes, services and any response model (tasks 5.x, 7.x); password hashing and the token code (4.4, 7.x); `FILE_*` upload checks (8.1); list/sort query params (9.3); new error codes; a real phone-region default beyond international format.

## Acceptance criteria
- [ ] AC1 Given a sign-up body with a bad email, a 5-byte password and an unknown key, when posted, then 422 `VALIDATION_FAILED` and `details` names `email`, `password` and the unknown key as fields.
- [ ] AC2 Every request model rejects unknown keys (`extra="forbid"`).
- [ ] AC3 Email: valid address, at most 254 characters, validated raw (surrounding spaces rejected, as in Node), then lowercased.
- [ ] AC4 New password: 8 to 72 **bytes**, no character with `unicodedata.category == "Cc"`; current/sign-in password: 1 to 72 bytes. The 72-byte limit is the reason bcrypt can take it (P5 note).
- [ ] AC5 Phone: valid and in international format (leading `+`), stored form E.164.
- [ ] AC6 UUID fields accept a UUID string only.
- [ ] AC7 `details` never contains the submitted value (rules D8, P4), including for the new validators.
- [ ] AC8 `uv run ruff check .`, `ruff format --check`, `mypy`, `pytest tests/unit` pass; `openapi.json` unchanged or regenerated by command.

## Edge cases
| Case | Expected behaviour | Decided by |
|------|--------------------|-----------|
| Password with a tab, newline or NUL | rejected (category `Cc`) | scope doc, Node `password-rules.ts` |
| Password of exactly 72 bytes / 73 bytes | accepted / rejected | scope doc |
| Multi-byte password: 40 characters of 2 bytes | 80 bytes, rejected | byte rule |
| Email with surrounding spaces | 422, not trimmed | ENDPOINTS.md |
| Profile `email: null` | 422; other nullable profile fields accept `null` to clear | ENDPOINTS.md decision 18 |
| Field not sent in a profile update | unchanged (model default is "unset", not `None`) | ENDPOINTS.md |
| Phone without `+` | 422 | AC5 |

# POC-4.2 — Error contract

## Problem
Every error the API returns must have one shape (ADR-0003 rejected FastAPI's default 422 body: "clients would need two error shapes"). Today only the 413 of the body-limit middleware (task 1.6) uses `{"error": {...}}`; a raised domain error, a failed validation, an unknown route or a crash each get a different body (`{"detail": ...}` or plain text). Tasks 4.3 to 8.x need domain exceptions to raise and one place that turns them into responses.

## Goal / business value
Goal 2 (authentication): the web client tells "token rejected, refresh" (`UNAUTHORIZED`) from "bad credentials" (`INVALID_CREDENTIALS`) by code alone. Goal 1 (scaffolding): one mechanism a fork extends by adding a subclass.

## Scope
- in: `app/core/errors.py` (exception classes, error-body models, handlers, `register_error_handlers`), wiring in `create_app`, the 413 body built by the same helper, error responses declared in the OpenAPI contract, `docs/api/ERRORS.md`, tests.
- **out (explicit):** field-level validators and `extra="forbid"` models (task 4.3); JWT and auth dependencies that raise `UNAUTHORIZED` (4.4); any real route that raises a domain error; new error codes (a code beyond ADR-0003 needs a superseding ADR); i18n of messages (they are API strings for developers, not UI copy, rule D7); rate limiting.

## Acceptance criteria
- [ ] AC1 Each of the eight codes (`UNAUTHORIZED` 401, `INVALID_CREDENTIALS` 401, `INVALID_RESET_TOKEN` 400, `EMAIL_ALREADY_REGISTERED` 409, `FORBIDDEN` 403, `NOT_FOUND` 404, `VALIDATION_FAILED` 422, `INTERNAL_SERVER_ERROR` 500) has a test that raises it and asserts status and body `{"error": {"code", "message", "details"}}`.
- [ ] AC2 A body failing Pydantic validation returns 422 `VALIDATION_FAILED` with one `details` entry per field (`field`, `message`, `type`); the FastAPI `{"detail": [...]}` body never appears.
- [ ] AC3 `details` never contains the submitted value (a password in a bad sign-up body stays out of the response and the logs, rules D8, P4).
- [ ] AC4 An unexpected exception returns 500 `INTERNAL_SERVER_ERROR` with a generic message and no traceback when `APP_ENV` is not `local`; in `local` the traceback is in `details`. It is logged with the stack either way.
- [ ] AC5 An unknown path answers 404 `NOT_FOUND` in the contract shape, not `{"detail": "Not Found"}`.
- [ ] AC6 The 413 of the body limit and the handlers build the body with the same function.
- [ ] AC7 `openapi.json` documents the error body for 422 and 500 (no `HTTPValidationError`), regenerated by command; the stale test passes.
- [ ] AC8 `docs/api/ERRORS.md` lists every code, status, meaning, when raised, the client rule for `UNAUTHORIZED`, and mapping decision 6 (413/422 for uploads).

## Edge cases
| Case | Expected behaviour | Decided by |
|------|--------------------|-----------|
| `HTTPException` raised by a dependency or Starlette (404 route, 405 method) | 404 becomes `NOT_FOUND`; 401/403 become `UNAUTHORIZED`/`FORBIDDEN`; other statuses keep their status and use `VALIDATION_FAILED` with empty `details` | assumption Q1 |
| Validation error inside a nested model or list | `field` is the dotted path without the leading `body`/`query` location, e.g. `profile.email`; location kept in a separate `in` key | assumption Q2 |
| A domain error carries `details` | passed through as given; default is `[]` | this spec |
| Exception raised after the response started | not convertible; Starlette handles it (already true for any handler) | framework |
| 500 on a route behind CORS | the response may lack CORS headers (ServerErrorMiddleware is outermost); checked in R3 and documented if true | R3 |

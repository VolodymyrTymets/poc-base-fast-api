**Revised after approval, on the human's instruction (what was built is in `spec.md`; where the text below still says otherwise, this note wins):**
there is no `Migration` table or model: Alembic's `alembic_version` records applied revisions. `0001_init` creates nine tables, not ten, and the PR is not split because the change edits the unmerged `0001_init` itself: [ADR-0018](../../decisions/ADR-0018-drop-migration-table.md).

Pattern followed: `app/core/db.py` and `app/config.py` for the URL (settings validated once, `create_engine` sets the UTC session time zone), Alembic's own async template
(`alembic init -t async`, Context7 cookbook) for `env.py`, and the table, index and foreign-key names in `app/models/*.py` and the Node DDL for the revision. Tests follow
`tests/unit/test_account_models.py` (no database) and `tests/e2e/test_db_file_models.py` (real Postgres, fixture that creates and removes only what it made).
Layer: none of `app/`'s. `migrations/` is tooling at the repo root: a new top-level directory and a new importer of `app`, so ADR-0017 extends ADR-0011 (`env.py` may import `app.config`, `app.core.db` and `app.models`; a revision imports nothing from `app`). No precedent exists for Alembic in this repo;
library facts checked with Context7 (rule D4): the async template, `command.check` raising `AutogenerateDiffsDetected`, `compare_server_default` off by default, `include_object`.

## Contract changes
- boundary: new CLI surface `alembic upgrade head`, `alembic downgrade base`, `alembic check` (via `uv run`); no HTTP, schema or setting change. `DATABASE_URL` is read as before.
- data: the first versioned schema (`alembic_version` table, nine tables, two enum types, extension `postgis`). Rollback: `alembic downgrade base` (extension stays), or drop the database; nothing existing is migrated.
- generated output: none; the revision is hand-written source. `uv.lock` changes through `uv add alembic` only (rule T3).

## Requirements (ordered, one commit each; branch `feat/POC-2.4-alembic-init-revision`, one draft PR)

### R1 — Dependency and async environment, no revision yet (M)
- files: `pyproject.toml` (change, ask-first: `alembic` runtime dependency; `migrations` added to `[tool.mypy] files`), `uv.lock` (by `uv add`), `alembic.ini` (new: `script_location = migrations`, no URL),
  `migrations/env.py` (new), `migrations/script.py.mako` (new), `migrations/versions/` (new, empty), `tests/unit/test_alembic_env.py` (new).
- layer: tooling. `env.py` takes `get_settings().database_url` (a missing one raises `alembic.util.CommandError` naming `DATABASE_URL`, which the CLI prints as `FAILED: ...` without a traceback; confirmed against the installed source in R1, rule D4), sets `target_metadata = Base.metadata` after `import app.models`, builds its engine with
  `create_engine(get_settings())` from `app/core/db.py` unchanged (one source for the UTC session rule; the default pool is fine for a one-shot command, and the engine is disposed), `compare_type=True`, `compare_server_default=True`, and `include_object` that skips only the reflected table `spatial_ref_sys` that has no metadata counterpart. Offline mode renders from the same URL.
- test: `ScriptDirectory` loads from `alembic.ini` with the absolute path (the autouse fixture changes the working directory); `alembic.ini` holds no `postgresql` URL; with `DATABASE_URL` unset `command.upgrade(cfg, "head", sql=True)` raises `CommandError` naming it (AC4); with a dummy URL it renders offline without connecting.
- executed how: `uv run alembic heads` (no output, exit 0) and `DATABASE_URL=postgresql+asyncpg://offline/x uv run alembic upgrade head --sql` (offline: no connection), output pasted; and the CLI with `DATABASE_URL` unset, run from an empty temporary directory so no `.env` is read (`uv run --project <repo> alembic -c <repo>/alembic.ini upgrade head`), showing the `FAILED:` line. The live-connection path is exercised in R3; the CLI is never pointed at the `.env` database.
- risk: strict mypy on `env.py` (Alembic's `context` proxy). Experiment first: run `uv run mypy` right after adding `migrations` to `files`; if it needs `type: ignore`, stop and ask instead of adding one (S3).

### R2 — Revision `0001_init` (L)
- first step, before the rest is written: one table (`Account`, with `AccountRole` and the enum it needs) and the `Account_createdAt_idx` `DESC` index, then `command.check` against a throwaway database (the R3 fixture, built here). It shows early whether `check` is clean on `TIMESTAMP(3)`, defaults, enums and `DESC`; the other nine tables follow only after.
- files: `migrations/versions/0001_init.py` (new), `tests/unit/test_initial_revision.py` (new).
- layer: tooling. `revision = "0001_init"`, `down_revision = None`. It does not import `app.models` (a revision is frozen). Order: `CREATE EXTENSION IF NOT EXISTS "postgis"`; `AccountRoleType` and `FileType` (`ENUM(..., create_type=False)` after an explicit create);
  tables `AccountRole`, `Account`, `AccountOnRole`, `AccountIdentity`, `File`, `AccountProfile`, `Notification`, `NotificationRecipient`, `DeletedHistory` with every name, type, nullability, default, primary key and foreign key action as in the models and the final Node DDL
  (`File.content` `bytea`, no `File.key` or `File.status`, no `SSN` / `is18YearOld`); then the twelve indexes (`createdAt DESC` through `sa.text`). Downgrade: indexes and tables in reverse, then both enums; the extension stays. The docstring holds the rollback note (what `downgrade` removes, that the extension and the data in dropped tables are not recoverable).
- test: offline SQL of `command.upgrade(cfg, "head", sql=True)` (AC5): the set of `CREATE TABLE`, `CREATE TYPE`, `CREATE INDEX` names and the foreign-key constraint names equals those on `Base.metadata`, derived from it; `SSN`, `is18YearOld`, `"key"` and `"status"` are absent; `ScriptDirectory` has exactly one head, `0001_init`; the downgrade SQL (`sql=True` from head to base) drops every created table and type.
- executed how: the offline `--sql` output read against `../poc-base/api/prisma/migrations/*/migration.sql` (counts: 2 enums, 9 tables, 12 indexes, 9 foreign keys), pasted; the live run is R3.
- risk: a type or default that differs from the models shows only in R3's `check`. The first R3 run is the experiment; fix the revision, never relax `check`.

### R3 — Real-Postgres migration test (M)
- files: `tests/e2e/test_db_migrations.py` (new).
- layer: tests (rule P8). A fixture creates `poc_migrations_<hex>` with an AUTOCOMMIT connection to the server in `TEST_DATABASE_URL`, points `DATABASE_URL` at it (`monkeypatch` plus `get_settings.cache_clear()`), and drops it with `DROP DATABASE ... WITH (FORCE)` in teardown; it only ever drops a name it generated. `command.*` runs in `asyncio.to_thread` because `env.py` calls `asyncio.run`.
- test: AC1 (`alembic_version` = `0001_init`, extension present, table, enum, index and foreign-key names equal to `Base.metadata`'s, read from `pg_catalog`); AC2 (`command.check` passes; after `DROP INDEX "File_createdAt_mimeType_idx"` it raises `AutogenerateDiffsDetected`); AC3 (downgrade to base leaves no application object, then upgrade again).
- executed how: `uv run pytest tests/e2e/test_db_migrations.py -v` against the scratch server named in `.env.test`, confirmed with the human first (Q6); output goes in the PR. Local server today: PostgreSQL 18.4 with PostGIS 3.6.4 available, superuser role.
- risk: `check` false positives (server defaults, `DESC`, enums, `TIMESTAMP(3)`); a leftover `poc_migrations_*` database after a crash is named in the RUNBOOK and never blocks a later run.

## Risks
| Risk | Impact | Cheapest way to find out early |
|------|--------|-------------------------------|
| `alembic check` reports false diffs on defaults, `DESC` or enums | AC2 cannot be met honestly | first R3 run; fix the revision or the hook for the specific case, ask if it needs relaxing |
| PostGIS adds objects the metadata lacks | `check` fails | the R3 run shows them; the hook already skips `spatial_ref_sys` only |
| Test creates a database on a server I did not set up | rule C4 | the human confirms the server first; only generated names are dropped |
| Strict mypy cannot type `env.py` | AC6 | run mypy at the end of R1; stop and ask rather than add an ignore |
| A revision differs from the Node DDL in a way the models share | 2.5 parity diff | read the offline SQL against the four `migration.sql` files in R2 |
